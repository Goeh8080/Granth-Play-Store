# Feature parity: ashok8090/Granth-Play-Store → Flutter

**Source audited:** upstream `main` of ashok8090/Granth-Play-Store (221 files):
- the shipped web bundle `mobile/android/app/src/main/assets/web/index.html`;
- its TypeScript sources in `src/` (`components/granth/*`, `lib/granth/*`, `styles.css`, `routes/*`);
- the Expo / React Native shell `mobile/App.tsx` and `app.json`;
- the native Kotlin `MainActivity` / `DownloadsModule` / `GranthBack`;
- `AndroidManifest.xml`, the `public/open` share page and `assetlinks.json`.

**Tools:** REA `analyze_javascript_application` on the extracted bundle, then a line-by-line read of the sources. Round 4 (2026-10-21): REA `open_binary` + `analyze_javascript_application` on the shipped bundle again (the whole 730 KB bundle exceeds REA's analyzer heap, so the app component `cg()` was extracted and analyzed on its own) to confirm the sync wiring (`setInterval(…, 18e4)` = every 3 min + on `online`, `granth-resume` / `visibilitychange` → `sync().then(savePages)`) and the strip counter text; REA `identify_flutter_build` on the built APK. Round 5 (2026-10-21): REA connected (`binary_session` OK); `analyze_javascript_application` on extracted components of the shipped bundle (grid switch `grid.js`, settings sheet `settings.js`, card looks `theme.js`: look list `$h`, `eg()` and the `html.ui-*` CSS). It confirmed the storage keys (`granth-cols`, `topic-cols`, `praman-cols`, `gallery-cols`, `ui-cols`, `granth-look`), the defaults, "state first, then localStorage", and that a look only restyles `.card` (plus `.dash-card` for combo).

**Rule followed:** same UI and behaviour; animations are smoother. Where the original had a bug, the correct behaviour was built instead (see the last section).

**Legend:** ✅ done (same behaviour) · ➕ done and improved · ⏭ not ported (with the reason).

## Bugs found in the original app (not copied)

1. **PDF memory grows with the book.** `buildBookPdf` keeps every prepared picture in `shots[]` and the whole PDF in memory. It is then base64-chunked through the WebView bridge, which takes 3–4× the PDF size. Big granths can run out of memory.
   - Here: at most 3–8 pictures are held at a time, and pages stream to disk from a background isolate.
2. **Huge photos.** `fitShot` returns the original image when the canvas decode fails. A 60-megapixel page is then embedded as-is, or crashes the WebView.
   - Here: native reduced-size decode. Without native support, a placeholder page is used instead of decoding it.
3. **A failed picture is silent.** It becomes a page without the picture and nothing says why.
   - Here: the page shows "चित्र उपलब्ध नहीं…" and the row reports how many pictures were missing.
4. **Error text.** A failed PDF shows `error.message`, often English or technical.
   - Here: a clear Hindi message with "फिर कोशिश करें". Low storage gets its own message.
5. **Only one PDF at a time.** A long granth blocks every other request in the कतार.
   - Here: parallel slots.
6. **Tray cap of 12 rows.** `tasks.slice(0, 12)` could drop a still-running job from the list.
   - Here: only finished rows are trimmed.
7. **Finished PDFs stay in memory.** Their `Blob`s stay in RAM in the task list.
   - Here: files on disk only.
8. **Same link opened twice.** `sentLink` de-duplicates by exact URL forever, so opening the same shared link a second time does nothing.
   - Here: a 5 s de-dup window.
9. **Shared links could reach a blank screen.** A link delivered before the WebView was ready, and resume after the WebView renderer died, both needed a reload hack.
   - Here: native routing. The link is applied before the first frame.
10. **Dead layout controls.**
    - The Flutter port's own regression: 1×1 crashed into an empty screen, and the settings did not refresh open screens.
    - The original's grid worked; the port now matches it.
11. **Partial files.** No cleanup after a crash mid-save; MediaStore rows could stay pending.
    - Here: `.part` files, cleanup at start, and delete-on-failure.
12. **No free-space check.** A full disk fails late with a generic error.
    - Here: space is checked first, and ENOSPC is mapped to a clear message.
14. **Failed downloads counted as saved.** The original `savePages` counted a failed picture as done and always ended with done = total, with no retry. The strip then said "सभी पेज इस डिवाइस पर सेव हैं" even when pictures were missing.
    - Here: 3 tries plus a second pass. Failures are counted and tried again on the next sync. A granth is marked offline only when all of its pictures are saved.
15. **No storage guard for page downloads.** The original kept downloading until the disk was full.
    - Here: the download stops below 150 MB free.
16. **Frozen sync strip.** In the port the strip was a `const` child inside the store listener, so its spinner and text never changed after a tap ("tap does nothing"). When all pages were saved, the page step ended at once, so no progress showed. Fixed: the strip rebuilds from the store, and manual sync always checks pages visibly.
17. **Counters restarting from 0.** The splash returned its child in a different tree position when it finished, which rebuilt the whole shell. Fixed with a stable key; counters remember what they already showed.
18. **Page counter showed 0 while pages were downloading.** The number came from the running download pass's own tally, which the silent start-up check restarted from 0 (it counted files as it re-checked them) and every sync replaced. Fixed: one live count of the files really on the phone (see "Visible download progress").
19. **PDF notification not visible on some phones.** Progress channel was IMPORTANCE_LOW (hidden in "silent" folds), notifications that the phone switched off were never detected (no dialog on Android ≤ 12), and the permission answer was never checked. Fixed as described under "Background PDF + notification".
24. **PDF pictures down-scaled (ashok's `Um`).** A JPEG is passed through only if it is ≤ 1800 px and < 1.1 MB; everything else is redrawn on a canvas at max 1800 px and re-encoded as JPEG q0.9, PNGs included. About 37 % of the library's pages (median 2,356 px, up to 8,632 px) lost resolution in every PDF. The port had copied a milder version (2,600 px / 1.5 MB, then 1,800 px q85). Fixed in round 6: original pictures are embedded untouched (see "Picture prep").
25. **Sync-strip page counter stuck (port bug, round 6).** `ImageStore.get` cleaned its in-flight map with `whenComplete(() => _inflight.remove(path))`; the arrow returned the removed future, i.e. the very future being completed, so every `get` waited on itself forever. Each download worker hung after its first page; pages only moved when the next 2-minute sync started fresh workers, and a PDF waiting for an unsaved page timed out (45 s) and retried. Ashok's `xe` map uses `.finally(() => { delete … })` (returns nothing), so his app did not have it; the port's arrow function did. Fixed, with a real-HTTP test that fails before and passes after. The strip now ticks per saved page (throttled to ~3 updates a second), in the foreground and while the background service runs.
13. **Dashboard counts.** They stayed at 0 until you navigated away and back after the first sync (port regression, fixed).
20. **Lists ignore the layout switch until reopened.** In ashok's app only the gallery listens for `granth-layout`; an open topic / granth / praman list keeps its old column count after सेटिंग → लेआउट until you leave and come back. The port updates every open list at once.
21. **Two border colours on a rounded card (combo look).** `inset 0 1px white` + `inset 0 -8px` base: in Flutter two border colours cannot be drawn with round corners (debug error, square corners in release). The 1 px white line (nearly invisible) keeps its space but is not drawn.
22. **Round-4 jank (port regression, fixed in round 5).** During the first download every saved page rebuilt the whole home screen (~330 widgets, ~8× a second); the floating pill's progress bar animated forever (frames never stopped); the 2-minute sync decoded and re-encoded the ~1.5 MB catalog on the UI thread and rebuilt the home screen even when nothing changed; the sticky header blurred the content under a 96 %-opaque bar on every scroll frame. Fixed: a separate, throttled page counter (~3 updates a second, only the strip and sync card listen), pill removed, catalog parsing / compare / file text in a background isolate, an unchanged sync updates only the "last sync" time, no blur under the header, round-3 scroll physics and page transition.
23. **Fallback font never registered (port).** Every text style named `NotoDevaFull` as its last fallback, but the font was only bundled as a plain file, so the fallback did nothing. It is now registered as a font family.

## Round 7 — blank pages, PDF card pager, load speed, kept data, scroll restore, signing

26. **Blank PDF pages (ashok's `Um` / `fitShot` path + port).** A page whose picture was not on the phone or could not be decoded became a page with no picture and the PDF still said "done". Here: every missing picture is downloaded first (prefetch, retry with back-off, waits for the network and resumes by itself on reconnect); each embedded picture is validated (decodable, non-zero size, EXIF-rotated JPEGs, CMYK / 16-bit / progressive / truncated / garbled files from `test/fixtures/pages`); if a page still cannot be built the job fails with a Hindi message ("N पेज के चित्र नहीं मिले…") and a "फिर कोशिश करें" button instead of writing a PDF with holes. When every page is already saved the fast path is unchanged (no prefetch pass, no extra waiting). Covered by `test/no_blank_pages_test.dart`.
27. **PDF card pager (ashok's `pdf_card_pager`).** ashok shows ONE job card at a time with an "अगला" arrow to step through the queue. The port listed every job. Now the dropdown shows one card, with पिछला / अगला pills and a position label; a new job is inserted first. ashok's pager keeps showing a stale index after the job it points to is removed; here the index is clamped. `test/pdf_pager_test.dart`.
28. **Load speed.** Start-up ran the connectivity check after parsing `catalog.json`; they now run together. Kabir Sagar ordering rebuilt its regexes on every comparison (precompiled, per-row key). Timings (box, release-like VM, 330 topics / 104 granths / 823 pramans, catalog.json 989 KB): parse 83 ms; boot → data 112 ms cold, 46–61 ms with 985 saved pictures; Kabir Sagar granth view 40–62 ms → 1.4–7 ms. Full download: 985 pictures, 568.8 MB in 73.7 s with 8 workers (bandwidth-bound; 16 workers 76.1 s, so 8 stays), first picture at 1.9 s. API: getGranths 64 KB 2.0 s, getPramans 1.26 MB 2.75 s, getTopics 193 KB 2.2 s (server time, not app time). `test/load_profile_test.dart` (skipped without /tmp/bench).
29. **Kept app data across versions.** ashok's data (`localStorage` keys, files under his data folder) has no version marker, so a newer build cannot tell an old layout from a new one and a bad value is thrown away. Here `DataCompat` (`kDataSchema = 1`) migrates in place, never deletes, keeps an unreadable `catalog.json` as `catalog.json.unreadable`, tolerates wrong value types in preferences restored from a backup, strips a BOM, keeps unknown gallery rows and fields, and finds files that moved. Any version code can read data written by any other. `test/data_compat_test.dart`.
30. **Scroll position lost on back (port and ashok).** Going back rebuilt the list from the top with undecoded pictures about 0 px tall, so the saved offset was larger than the list ("clamped"), and the search text was forgotten so a filtered offset pointed at the wrong rows. Here: pictures get their final height from the file header before decoding (`ImageSizes`; rotated JPEGs are measured once after decoding), the restore keeps trying each frame until the exact offset holds, and the search text is saved with the place. Dashboard and Gallery now have places too. Works for every grid size (1×1, 2×2, 3×3), zoomed views, and chains (Dashboard → Granth list → granth → page → back → back). `test/scroll_restore_test.dart` (one test fails when the header-size fix is disabled).
31. **Release signing.** The release build is signed with the project key when `android/key.properties` exists (gitignored; points at the keystore outside the repo) and falls back to the debug key when it does not, so CI and fresh clones still build. The keystore and password are never in the repo.

## Round 8 — pop animations, ashok's PDF deck, one notification, kept data, highlighter speed

32. **Deck re-opens whenever the first running PDF changes (ashok).** His effect depends on the id of the first running job, so finishing one PDF of a queue pops the deck open again over whatever the user was doing. Not copied: here it opens once per newly started PDF and stays shut after बंद.

36. **Animation setting (एनिमेशन चालू / कम).** Default चालू; "कम" and the phone's "remove animations" (`MediaQuery.disableAnimations`) switch off only the new decorative motion (pop, blur-focus, inner stagger, app-open fade). Navigation, the count-up, the tilt and the splash are not touched.

38. **One notification, not one per PDF.** One ongoing progress notification (fixed id, `onlyAlertOnce`, ≈2 updates/s) and ONE summary when the run ends ("50 PDF तैयार"), replaced by the next run. The page-sync notification joins the same group. All of them use the monochrome `ic_stat_granth` (flat white open book, alpha only; `tool/icon_mask.py` exports and checks the mask). The round-7 build posted one heads-up per finished PDF and used a page-shaped icon for sync.

## Round 11 — 2×2 folders, religion symbols, Back fix, तत्त्व AI entry

No image or font files; about 3 KB of path data. Preview: `PREVIEW_OUT=preview.png flutter test test/preview_religions_test.dart`.
50. **Back after recents.** Root cause: Flutter only tells Android that it handles Back (`setFrameworkHandlesBack(true)`) when the Dart side sends it, and only to the *current* Activity. While a PDF or page download runs the engine outlives the Activity, so after reopening from recents a new Activity attached to the old engine, Dart never resent the flag and Back fell through to Android's default (close the app). Fix: `MainActivity` forces the callback on for every Activity (create, resume, and ignores `false`), and Dart re-sends it on every resume. Also the saved back stack is now restored after process death (`AppNav.restore`, rebuilt from the screen if missing). The exit rule itself is untouched: only the dashboard asks 'क्या आप बाहर निकलना चाहते हैं?' and the app closes only on "हाँ". Tests: `test/round11_test.dart` (needs a real phone for the Activity part).
